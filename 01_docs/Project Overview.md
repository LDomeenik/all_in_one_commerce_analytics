
# 프로젝트 설계서

```
본 프로젝트는 이커머스 데이터를 업로드하면 자동으로 분석을 수행하는
All-in-One 데이터 분석 서비스 구축을 목표로 합니다.

사용자가 별도의 데이터 전처리나 분석 지식 없이도
데이터를 업로드하는 것만으로 컬럼 자동 매핑, 전처리, 분석 가능 여부 진단을 거쳐
KPI 분석, 코호트 분석, RFM 분석, 상품 분석 등의 
핵심 인사이트를 도출할 수 있도록 설계하였습니다.

또한 단순 분석 결과 제공을 넘어서,
데이터 파이프라인 ((Raw → Staging → Data Mart) 구조와
분석 모듈을 분리하여 설계함으로써
재사용 가능하고 확장 가능한 분석 시스템을 구축하는 것을 핵심 목표로 합니다.
```


---

## 1. 문제 정의

```
이커머스 데이터 분석은 기업의 매출 구조, 고객 행동, 상품 성과 등을 파악하기 위한 
핵심 과정이지만, 실제 분석 과정에서는 여러 가지 비효율과 진입 장벽이 존재합니다.

구체적인 문제는 다음과 같습니다.

- 기업마다 다른 데이터 구조
- 실제 분석 구현을 위한 코딩 작업
- 반복 작업의 비효율성
  
이러한 문제로 인해 데이터 분석은 효율적으로 수행되기 어렵고,
분석 결과의 활용 또한 제한되는 구조를 가지게 됩니다.
```

- **기업마다 다른 데이터 구조**
	- 분석을 수행하기 위해서는 컬럼 정의, 데이터 정제, 전처리 과정을 반복해야 함
	- 동일한 분석이라도 데이터 구조에 따라 매번 다른 방식으로 구현해야 함
	- 이 과정에서 많은 시간과 비용이 소요되며, 분석의 일관성이 저하됨

- **실제 분석 구현을 위한 코딩 작업**
	- KPI 분석, 코호트 분석, RFM 분석 등 주요 분석은 SQL 및 데이터 처리 지식이 필요함
	- 분석 로직을 직접 구현해야 하므로 비전문가의 접근이 어려움
	- 결과적으로 데이터 분석이 특정 인력에 의존하는 구조가 발생

- **반복 작업의 비효율성**
	- 유사한 분석을 수행할 때마다 동일한 전처리 및 분석 로직을 반복적으로 작성해야 함
	- 재사용 가능한 구조가 없어 분석 효율이 낮고 유지보수가 어려움
	- 분석 자동화가 이루어지지 않아 확장성과 활용도가 제한됨


---

## 2. 목적 및 기대효과

```
본 프로젝트는 이커머스 데이터 분석 과정에서 발생하는 구조적 비효율을 해결하고,
데이터 분석의 진입 장벽을 낮추기 위한 자동화된 분석 환경 구축을 목표로 합니다.

특히, 데이터 업로드만으로 전처리부터 주요 분석까지 자동으로 수행되는 구조를 설계함으로써
분석의 효율성과 재사용성, 확장성을 동시에 확보하고자 합니다.
```

- **목적**
	- 다양한 데이터 구조를 표준화하여 분석 가능한 형태로 변환
	- 컬럼 매핑 및 전처리 과정을 자동화하여 반복 작업 최소화
	- KPI, 코호트, RFM 등 핵심 분석을 자동으로 수행할 수 있는 환경 구축
	- 분석 로직과 데이터 구조를 분리하여 재사용 가능한 분석 시스템 설계

- **기대 효과**
	- 데이터 전처리 및 분석에 소요되는 시간과 비용 절감
	- 비전문가도 데이터 분석을 수행할 수 있는 환경 제공
	- 표준화된 분석 구조를 통한 일관된 분석 결과 확보
	- 분석 자동화를 통한 확장성과 유지보수 향상

## 3. 범위 및 전제

```
본 프로젝트는 다양한 이커머스 데이터를 입력받아
표준화된 구조로 변환한 후 주요 분석을 자동으로 수행하는 것을 범위로 합니다.

단, 모든 형태의 데이터를 완벽하게 처리하는 것을 목표로 하기보다는
일반적인 이커머스 데이터 구조를 기준으로 분석 가능한 범위를 정의하고,
해당 범위 내에서 안정적인 분석 결과를 제공하는 것을 목표로 합니다.
```

- **프로젝트 범위**
	- CSV / Excel 형태의 이커머스 데이터 업로드 지원
	- 컬럼 자동 매핑을 통한 데이터 구조 표준화
	- 전처리 및 데이터 정합성 검증 수행
	- 분석 가능 여부 진단 기능 제공
	- KPI 분석, 코호트 분석, RFM 분석, 상품 분석 등을 수행
	- Streamlit 기반 분석 결과 시각화 제공

- **프로젝트 전제 조건**
	- 입력 데이터는 기본적인 이커머스 거래 데이터를 포함해야 함 (주문, 고객, 상품 등)
	- 필수 컬럼이 존재하지 않을 경우 일부 분석 기능은 제한될 수 있음
	- 컬럼 자동 매핑은 사전 정의된 규칙을 기반으로 수행됨
	- 데이터 품질(결측치, 이상치)에 따라 분석 결과가 영향을 받을 수 있음
	- 본 프로젝트는 분석 자동화에 초점을 두며, 데이터 수집 단계는 포함하지 않음

## 4. 프로젝트 전체 Flow

```
본 프로젝트는 사용자가 데이터를 업로드하면
데이터 처리부터 분석 결과 도출까지 전 과정을 자동으로 수행하는 구조로 설계되었습니다.

전체 흐름은 다음과 같습니다.

1. 데이터 업로드
2. 컬럼 자동 매핑
3. 데이터 전처리 및 정합성 검증
4. 분석 가능 여부 진단
5. 분석 모듈 실행
6. 분석 결과 시각화 및 대시보드 제공
```

- **데이터 업로드**
	- CSV / Excel 파일을 입력받아 분석을 시작

- **컬럼 자동 매핑**
	- 입력 데이터의 컬럼을 표준 컬럼으로 자동 매핑
	- 다양한 데이터 구조를 분석 가능한 형태로 변환

- **데이터 전처리 및 정합성 검증**
	- 결측치 처리, 데이터 타입 변환 등 전처리 수행
	- 데이터 오류 및 이상 여부 검증

- **분석 가능 여부 진단**
	- 필수 컬럼 존재 여부 및 데이터 품질 기준 확인
	- 이를 기반으로 각 분석 모듈의 실행 가능 여부 판단

- **분석 모듈 실행**
	- KPI 분석, 코호트 분석, RFM 분석, 상품 분석 수행
	- 표준화된 분석 로직 기반의 결과 생성

- **분석 결과 시각화 및 대시보드 제공**
	- Streamlit UI를 통해 분석 결과를 시각적으로 제공
	- 주요 지표 및 인사이트 확인 가능

## 5. 핵심 분석 모듈

```
## 5. 핵심 분석 모듈

본 프로젝트는 다양한 이커머스 분석을 모듈 단위로 확장 가능하도록 설계되었습니다.

현재는 핵심 분석(KPI, 코호트, RFM, 상품 분석 등)을 중심으로 구성되어 있으며,
향후 퍼널 분석, LTV 분석, AARRR 분석 등 추가적인 분석 모듈을 확장할 수 있도록 
구조를 설계하였습니다.

※ 각 분석 모듈에 대한 상세 정의 및 로직은 별도의 문서에서 관리합니다.
```

## 6. 문서 구조 및 설계 기준

```
본 프로젝트는 분석 로직과 데이터 구조의 재사용성과 확장성을 확보하기 위해
핵심 설계를 문서 단위로 분리하여 관리하도록 설계하였습니다.

각 문서는 서로 독립적인 역할을 가지며,
분석 기능 추가 또는 구조 변경 시에도 전체 시스템에 영향을 최소화할 수 있도록 구성하였습니다.

설계 기준은 다음과 같습니다.

- 분석 로직과 데이터 구조를 분리하여 관리
- 모든 분석은 표준화된 데이터 구조를 기준으로 수행
- 재사용 가능한 모듈 단위로 분석 기능을 구성
- 신규 분석 기능은 기존 구조를 변경하지 않고 확장 가능하도록 설계
- 문서 기반 설계를 통해 분석 기준의 일관성과 유지보수성을 확보
```

- **문서 구성**
	- KPI 정의서
		- 주요 지표의 정의 및 계산 기준을 관리
	- 데이터 명세서
		- 데이터 구조, 컬럼 정의, 테이블 설계를 관리
	- 분석 모듈 설계서
		- 각 분석 모듈의 로직 및 처리 흐름 정의
	- 컬럼 매핑 정책서
		- 다양한 데이터 구조를 표준 컬럼으로 변환하는 기준 정의
	- 전처리 정책서
		- 데이터 정제, 결측치 처리, 데이터 타입 변환 기준 정의

## 7. 데이터 처리 및 분석 흐름

```
본 프로젝트는 다양한 이커머스 데이터를 안정적으로 처리하고
일관된 분석 결과를 제공하기 위해 단계별 데이터 처리 구조를 기반으로 설계되었습니다.

데이터는 업로드 이후 표준화, 전처리, 적재 과정을 거쳐
분석 가능한 형태로 변환되며, 이후 분석 모듈을 통해 결과가 생성됩니다.

데이터 처리 흐름은 다음과 같습니다.

- Raw Data
- Staging Layer
- Data Mart Layer
- Analytics Layer
```

- **Raw Data**
	- 사용자가 업로드한 원본 데이터를 그대로 저장
	- 데이터 손실 없이 원본 상태 유지

- **Staging Layer**
	- 데이터 타입 변환 및 컬럼 표준화 수행
	- 컬럼 자동 매핑 결과 반영
	- 결측치 처리 및 데이터 정합성 검증 수행

- **Data Mart Layer**
	- 분석 목적에 맞게 데이터 구조 재구성
	- KPI 및 분석에 필요한 기준 데이터 생성
	- 표준화된 분석 기반 데이터 제공

- **Analytics Layer**
	- Data Mart를 기반으로 분석 모듈 실행
	- KPI, 코호트, RFM 등 분석 결과 생성

## 8. 기술 스택 및 실행 구조

```
본 프로젝트는 데이터 처리, 분석, 사용자 실행 환경을 분리하여 설계하였으며,
각 영역에 적합한 기술을 선택하여 효율성과 확장성을 확보하였습니다.

사용한 기술 스택은 다음과 같습니다.

- Python
	- 데이터 처리 및 분석 로직 구현
	- 컬럼 매핑, 전처리, 분석 모듈 실행 담당

- SQL
	- 데이터 저장 및 구조화
	- Data Mart 설계 및 분석 기반 데이터 관리

- Streamlit
	- 사용자 인터페이스(UI) 구성
	- 데이터 업로드 및 분석 결과 시각화 제공

실행 구조는 다음과 같습니다.

- 분석 환경
	- SQL 기반 데이터 파이프라인 구축(Raw → Staging → Data Mart)
	- 분석 로직 및 KPI 정의 관리

- 사용자 실행 환경
	- Python + SQL 기반 경량 실행 구조
	- 사용자는 별도의 데이터베이스 구축 없이 분석 수행 가능

- 확장 구조
	- FastAPI 기반 백엔드 확장 가능
	- React 기반 프론트엔드 분리 가능
	- 분석 결과 저장 및 재사용 구조로 확장 가능
```
